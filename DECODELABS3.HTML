Choosing the Right Blueprint for Your Data

Understand the difference between SQL and NoSQL databases.

SQL (Relational)

  • Structured Tables
  • ACID Transactions
  • Fixed Schema
  • Complex Relationships
  • Examples: MySQL, PostgreSQL

NoSQL (Non-Relational)

  • Schema-less
  • Highly Scalable
  • Flexible Data
  • Fast Performance
  • Example: MongoDB

The Fundamental Operations of State Persistence

Create

Adding new data entries into the memory vault.

Read

Retrieving and viewing existing data entries.

Update

Modifying the details of existing data entries.

Delete

Removing unwanted or obsolete data entries.

Mapping Database Actions to the Web

CREATE = HTTP POST = SQL INSERT

POST is non-idempotent; identical requests create multiple new resources.

READ = HTTP GET = SQL SELECT
UPDATE = HTTP PUT = SQL UPDATE

(or PATCH for partial updates)

DELETE = HTTP DELETE = SQL DELETE

The Database is the
Final Source of Truth

Databases must never trust application logic blindly. Data integrity must be enforced strictly at the schema level.
UNIQUE
Enforces that all values in a column are entirely distinct. Prevents duplicate usernames or email addresses.
NOT NULL
Ensures a column can never be left empty. Critical data points must always be provided.
CHECK
Imposes a strict mathematical or logical condition on the values allowed in a column (e.g., age >= 18).
